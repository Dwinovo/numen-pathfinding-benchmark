# Numen 寻路评测数据集 / Numen Pathfinding Benchmark

三维带重力格子上的寻路评测:固定的地形(七块 512×512 的原版世界生成地图)、840 道自动出的题,以及每道题在 **GRAV3D** 规则下的最优答案与参考路径。地形是一个字节一格的普通数组,规则写成文档,答案有独立的验证器和参考求解器——不需要 Minecraft,任何做路径规划、机器人导航、游戏 AI 的人都能用。
A 3D grid pathfinding benchmark with gravity: seven fixed 512×512 terrain regions generated by Minecraft 1.21.1, 840 generated problems, and for each problem the optimal answer and a reference path under the **GRAV3D** rules. The terrain is a plain one-byte-per-cell array, the rules are written down, and answers come with an independent validator and a reference solver — no Minecraft required, for anyone working on path planning, robot navigation or game AI.

[Numen](https://github.com/Dwinovo/minecraft-numen) 的寻路模块也用它评测:包里保留着 Minecraft 的原始区域文件、v2 的题库,以及 Numen 自己的寻路在它的成本模型下算出的标准答案(下称"Numen 层")。
[Numen](https://github.com/Dwinovo/minecraft-numen)'s pathfinding module is evaluated with it too: the package keeps the original Minecraft region files, the v2 problem files, and the reference answers Numen's own planner computed under its own cost model (the "Numen layer" below).

## 两层 / Two layers

| | GRAV3D 层(v3 新增) / GRAV3D layer (new in v3) | Numen 层(v2) / Numen layer (v2) |
|---|---|---|
| 地形 / terrain | `neutral/`:类别码字节网格 / class-code byte grid | `terrain/`:`.mca` 区域文件 / Minecraft region files |
| 规则 / rules | [RULES.md](RULES.md):`grav3d-1.0`,任何人可实现 / anyone can implement | Numen 的搜索与成本模型 / Numen's own search and cost model |
| 题 / problems | `scenarios/<地>.csv`,局部坐标 / local coordinates | `problems/<地>.jsonl`,世界坐标 / world coordinates |
| 答案 / answers | `grav3d/answers/`:最优价 + `grav3d/paths/`:参考路径,**可独立验证** / optimal cost + reference paths, **independently verifiable** | `answers.jsonl`:Numen 模型算出的参考值 / reference values from Numen's model |

两层是同一批题(同样的 id、距离档、dev/held 划分),题只换了坐标。GRAV3D 层的"最优"只相对 [RULES.md](RULES.md) 里写明的规则;Numen 层的"最优"相对 Numen 的状态抽象与成本模型,不能当作公共基准。
Both layers hold the same problems (same ids, distance buckets, dev/held split); only the coordinates differ. "Optimal" in the GRAV3D layer is relative to the rules written in [RULES.md](RULES.md); in the Numen layer it is relative to Numen's own state abstraction and cost model and is not a public yardstick.

## GRAV3D 规则一页纸 / GRAV3D in a nutshell

身体占上下两格;站得住 = 脚头两格可通行且脚下是支撑,或脚在静水里/可攀爬格里。走法:4 向平走、4 向不切角的斜走、上一级、走出边沿下落(落在实心上最多 3 格,落进水不限)、爬梯、水中 6 向游。**赛道 A** 不改地形;**赛道 E** 另加挖开挡路的格、向下挖、搭桥、垫柱,改动不持久(每步前提只读原始地图,状态只有位置)。图外是墙。代价是整数毫刻,目标是最短时间。完整定义见 [RULES.md](RULES.md)。
The body occupies two cells; it stands when both are free and it rests on a solid cell, or floats in still water, or hangs on a climbable cell. Moves: 4-way walk, 4-way diagonal without corner cutting, step up one, walk off an edge and fall (at most 3 cells onto a solid, any depth into water), ladders, 6-way swimming in water. **Track A** does not edit the world; **track E** adds digging out obstacles, digging down, bridging and pillaring, with edits that are not persistent (each step reads the original map only, the state is just the position). Outside the grid is a wall. Costs are integer millitick; the goal is the shortest time. The full definition is in [RULES.md](RULES.md).

地形类别(每格一个字节)/ terrain classes (one byte per cell): 空气 air、软 soft、石 stone、硬 hard、基岩 bedrock、静水 water、禁入 forbidden、可攀爬 climb、门 door、高障碍 tall;方块状态到类别由原版碰撞形状、硬度与语义算出,见 `blockmap.csv`。

## 题 / Problems

840 道(7 块 × 3 档 × 40),v2 起固定不变。一行一道题,坐标是局部坐标:
840 problems (7 regions × 3 buckets × 40), unchanged since v2. One problem per line, coordinates are local:

```
id,region,bucket,split,sx,sy,sz,goal,gx,gy,gz,radius
hills-short-001,hills,short,dev,361,130,414,at,350,128,414,
```

- **距离档 / bucket**:起终点的三维直线距离,短 ≤32、中 32–128、长 128–400 / 3D straight-line distance, short ≤32, medium 32–128, long 128–400。
- **目标 / goal**:走到某格(`at`)、走到某格附近 r 格内(`near`)、挖到某格(`dig`,只对封闭在实心里的一格,只有赛道 E 适用)/ walk to a cell, walk within r of a cell, dig a cell (a cell sealed in rock; track E only).
- **dev / held**:地块 1–6 的题按题号哈希五五开,一半调参用(`dev`),一半封存(`held`,只在定版前跑);`mixed` 全部是 `held` / regions 1–6 split 50/50 by id hash into tuning (`dev`) and held-out (`held`); `mixed` is all `held`.
- 题是 v2 时用 Numen 的搜索与成本模型挑出来的(只收在 Numen 的规则下有定论的题),所以难度分档和"哪些题有趣"带着 Numen 的偏好;答案则不是——GRAV3D 的答案由独立的参考求解器在 GRAV3D 规则下重新算出。/ The problems were selected in v2 with Numen's search and cost model (only those conclusive under Numen's rules were kept), so the buckets and "which problems are interesting" carry Numen's bias; the answers do not — the GRAV3D answers are recomputed by an independent reference solver under the GRAV3D rules.

## 答案 / Reference answers

每道题在两个赛道上各一行:`optimal`(最优价,单位毫刻,与挖、放块数)、`unsolvable`(整个可达范围搜尽,没有目标;图是封闭的,所以这是证明)或 `n/a`(这一赛道不适用:起点在规则下站不住,或赛道 A 上的 `dig` 目标)。`optimal` 的每一行都有一条参考路径。
One row per problem and track: `optimal` (cost in millitick, plus digs and places), `unsolvable` (every reachable state was searched without meeting the goal; the grid is closed, so this is a proof) or `n/a` (not applicable on this track: the start cannot stand under the rules, or a `dig` goal on track A). Every `optimal` row has a reference path.

v3 的数 / counts in v3 (840 problems per track):

| 赛道 / track | optimal | unsolvable | n/a |
|---|---|---|---|
| A | 520 | 182 | 138 |
| E | 760 | 0 | 80 |

每块地的数在 `grav3d/manifest.json`。`n/a` 多出在 nether(147 条 A/E 合计):v2 的下界起点不少在岩浆里(GRAV3D 里岩浆禁入),mountains 里有一些起点在粉雪里。题没有删、id 没有改。
Per-region counts are in `grav3d/manifest.json`. Most `n/a` are in nether (147 over both tracks): many of v2's nether starts are inside lava (forbidden in GRAV3D), and some mountains starts are inside powder snow. No problem was removed and no id changed.

答案由 `tools/solver/Solve.java`(权重 1 的 A*,一致估价,平铺数组)算出,再由独立写的 `tools/validate.py` 逐条验证:1 280 条 optimal 路径全部合法、代价与参考最优价一致;短档题另用零估价(Dijkstra)重算,320 条"题×赛道"结论完全相同。一致性小图见 `tests/conformance/`。
The answers were computed by `tools/solver/Solve.java` (weight-1 A*, consistent estimate, flat arrays) and checked path by path with the independently written `tools/validate.py`: all 1,280 optimal paths are legal and their cost equals the reference optimum; short-bucket problems were also recomputed with a zero estimate (Dijkstra), and all 320 problem×track verdicts are identical. Conformance maps are in `tests/conformance/`.

## Numen 层(v2,原样保留) / The Numen layer (v2, unchanged)

`problems/<地>.jsonl` 一行一道题(世界坐标),带终点种类与几何标签:
`problems/<region>.jsonl` has one problem per line (world coordinates), with end class and geometric tags:

```json
{"id":"hills-medium-012","region":"hills","bucket":"medium","distance":93.4,
 "from":[x,y,z],"goal":{"type":"at|near|dig","to":[x,y,z],"radius":3},
 "endClass":"surface|cave|cavity|buried","split":"dev|held","tags":["water","rough","dig","underground"]}
```

- **终点种类 / endClass**:地表(含水面)、洞穴地面(连着大片空间)、封闭的地下空腔、封闭在实心里的一格 / surface (incl. water surface), cave floor (connected to a large open space), sealed cavity, a cell sealed in solid rock.
- **标签 / tags**:只看地形与题:起终点之间的直线上有水或岩浆(`water`)、直线不平稳(`rough`)、终点被封死要挖才进得去(`dig`)、终点在地下(`underground`)。/ geometric only: fluid on the straight line, a rough line, a sealed end that must be dug into, an underground end.
- **规格 / spec**:Numen 的搜索有两种规格,`A` 不挖不垫,`B` 出厂规格(可挖可垫、只看价钱);同一道题两种都跑,需要编辑才做得成的题只给 `B` 跑。/ Numen's search has two specs, `A` no digging or placing, `B` the factory spec (may dig and place, price only); every problem runs under both, except goals that need editing, which run under `B` only. (这与 GRAV3D 的赛道 A、E 是两回事 / not the same as GRAV3D tracks A and E.)
- **`answers.jsonl`**:一行一条"题 × 规格":`{"id":..,"spec":"A|B","status":"optimal|unsolvable","cost":..,"expanded":..,"startEstimate":..}`,是权重 1 的 A* 在整块区域上、Numen 的走法与成本模型下算出的最优价(先 2 000 000 个节点,撞上限的再 8 000 000 个);`unsolvable` 是区域内证明的无解(连通块没碰到区域边)。`answers-manifest.json` 记着算出它们的 Numen 提交与两档节点上限。评测读它;没有它评测照跑,只是报表里没有次优比。/ one line per problem × spec: the optimal cost from weight-1 A* over the whole region under Numen's moves and cost model (first 2,000,000 nodes, those that hit the cap again with 8,000,000); `unsolvable` is a no-route proven inside the region (the connected component did not touch the region edge). `answers-manifest.json` has the Numen commit and the two node caps.
- **只收有定论的题 / only conclusive problems**:候选题在每个适用规格下答案都是最优价或区域内证明的无解才收;路伸出区域的(区域外没加载,没有定论)、两档上限都算不动的、只有上界的、平凡的都拒掉,继续抽候选直到每块地每档凑满 40 道。v2 抽了 1 158 个候选,拒掉 318 个(平凡 14、路伸出区域 218、两档都算不动 63、只有上界 23);1 551 条答案里最优 1 272、无解 279。每块每档的数在 `manifest.json`。/ a candidate is kept only when its answer under every applicable spec is an optimal price or a no-route proven inside the region; routes leaving the region, those no node cap solves, those with only an upper bound, and trivial ones are rejected, and candidates are drawn until each region and bucket has 40. v2 drew 1,158 candidates and rejected 318 (trivial 14, beyond the region 218, too hard 63, upper bound only 23); of 1,551 answers 1,272 are optimal and 279 unsolvable. Per-region and bucket counts are in `manifest.json`.

出题与求解器的细节、假设(身体、垫路料、加载的区块、许可)见 [GENERATION.md](GENERATION.md) 与 Numen 仓库的 `docs/adr/pathing/0031-planning-benchmark.md`。
Generation details and the assumptions (body, materials, loaded chunks, permissions) are in [GENERATION.md](GENERATION.md) and Numen's `docs/adr/pathing/0031-planning-benchmark.md`.

## 怎么用 / Usage

提交自己的求解结果 / checking your own planner:

```
# 提交文件:每行一个 JSON,{"id":..,"track":"A|E","path":[[x,y,z],...]} 或 {"id":..,"track":..,"status":"unsolvable"}
python3 tools/validate.py --map neutral/hills --scenarios scenarios/hills.csv \
        --answers grav3d/answers/hills.csv --paths my-hills.jsonl --out verdicts.csv
```

每题的结论是 `valid`(附代价与最优价之比)、`invalid-<i>`(第 i 步非法,附原因)、`unsolvable-ok` 等,见 [FORMAT.md](FORMAT.md)。重新求解、跑一致性测试 / re-solve and run the conformance tests:

```
javac -d out tools/solver/Solve.java
java -cp out Solve --classes neutral/classes.json --costs grav3d/costs.json --map neutral/hills \
     --scenarios scenarios/hills.csv --tracks A,E --answers a.csv --paths p.jsonl --threads 8
python3 tests/conformance/run.py
```

求解器每个线程每个赛道占约 0.8 GB(两个与格子同大的整数数组);全部 1 680 个"题×赛道"在 20 核上约 2.6 分钟。
The solver uses about 0.8 GB per thread and track (two int arrays the size of the grid); all 1,680 problem×track jobs take about 2.6 minutes on 20 cores.

Numen 仓库里的 Numen 层评测(v2 格式,Gradle 按版本与 sha256 下载)/ Numen's own evaluation (v2 format, downloaded by version and sha256 from Gradle):

```
./gradlew :numen:pathing:pathingBench                              # 下载数据集,跑 dev 题 / download the dataset, run dev problems
./gradlew :numen:pathing:pathingBench -PpathingDataset=<本地目录>   # 用本地的数据集目录 / use a local dataset directory
./gradlew :numen:pathing:pathingExport -PpathingDataset=<目录> -PpathingExportOut=<目录>   # 重新导出中立地形 / re-export the neutral terrain
```
