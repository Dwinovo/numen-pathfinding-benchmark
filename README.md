# Numen 寻路评测数据集 / Numen Pathfinding Benchmark

三维带重力格子上的寻路评测:固定的地形(七块 512×512 的原版世界生成地图)、840 道自动出的题,以及每道题在 **GRAV3D** 规则下的最优答案与参考路径。地形是一个字节一格的普通数组,规则写成文档,答案有独立的验证器和参考求解器——不需要 Minecraft,任何做路径规划、机器人导航、游戏 AI 的人都能用。
A 3D grid pathfinding benchmark with gravity: seven fixed 512×512 terrain regions generated by Minecraft 1.21.1, 840 generated problems, and for each problem the optimal answer and a reference path under the **GRAV3D** rules. The terrain is a plain one-byte-per-cell array, the rules are written down, and answers come with an independent validator and a reference solver — no Minecraft required, for anyone working on path planning, robot navigation or game AI.

[Numen](https://github.com/Dwinovo/minecraft-numen) 的寻路模块也用它评测:包里保留着 Minecraft 的原始区域文件、Numen 评测读的题库,以及 Numen 的搜索在纯物理耗时口径下算出的参考值(下称"Numen 层")。
[Numen](https://github.com/Dwinovo/minecraft-numen)'s pathfinding module is evaluated with it too: the package keeps the original Minecraft region files, the problem files Numen's evaluation reads, and reference values Numen's search computed under a pure physical-time cost (the "Numen layer" below).

## 两层 / Two layers

| | GRAV3D 层(v3 新增) / GRAV3D layer (new in v3) | Numen 层 / Numen layer |
|---|---|---|
| 地形 / terrain | `neutral/`:类别码字节网格 / class-code byte grid | `terrain/`:`.mca` 区域文件 / Minecraft region files |
| 规则 / rules | [RULES.md](RULES.md):`grav3d-1.0`,任何人可实现 / anyone can implement | Numen 的搜索与成本模型 / Numen's own search and cost model |
| 题 / problems | `scenarios/<地>.csv`,局部坐标 / local coordinates | `problems/<地>.jsonl`,世界坐标 / world coordinates |
| 答案 / answers | `grav3d/answers/`:最优价 + `grav3d/paths/`:参考路径,**可独立验证** / optimal cost + reference paths, **independently verifiable** | `answers.jsonl`:Numen 的搜索按纯物理耗时算出的参考值(`numen-physical-1`,不是真最优)/ reference values from Numen's search under pure physical time (`numen-physical-1`, not a true optimum) |

两层是同一批题(同样的 id、距离档、dev/held 划分),只是坐标一个是世界坐标、一个是局部坐标。**v3 的题集与 v2 不同**:v2 的出题只要求"身体待得住",有不少起点、终点落在岩浆湖里(Numen 的搜索认为那里站得住,岩浆只是代价与排除的问题);v3 起终点的挑选还要求身体碰到的格不是路线规格排除的种类(岩浆、火、粉雪……),所以重新出了全部 840 题,题号对应的题大多变了——v2 的题、答案与基线不能和 v3 混用。GRAV3D 层的"最优"只相对 [RULES.md](RULES.md) 里写明的规则;Numen 层的"最优"相对 Numen 的状态抽象与成本模型,不能当作公共基准。
Both layers hold the same problems (same ids, distance buckets, dev/held split); only the coordinates differ (world vs local). **The v3 problem set differs from v2**: v2's generator only required that the body can stand, and many starts and goals ended up inside lava lakes (Numen's search thinks the body can stand there; lava is a matter of price and exclusion); v3 also requires that the cells the body touches are not of a kind the route spec excludes (lava, fire, powder snow, ...), so all 840 problems were regenerated and most ids now name different problems — v2 problems, answers and baselines must not be mixed with v3. "Optimal" in the GRAV3D layer is relative to the rules written in [RULES.md](RULES.md); in the Numen layer it is relative to Numen's own state abstraction and cost model and is not a public yardstick.

## GRAV3D 规则一页纸 / GRAV3D in a nutshell

身体占上下两格;站得住 = 脚头两格可通行且脚下是支撑,或脚在静水里/可攀爬格里。走法:4 向平走、4 向不切角的斜走、上一级、走出边沿下落(落在实心上最多 3 格,落进水不限)、爬梯、水中 6 向游。**赛道 A** 不改地形;**赛道 E** 另加挖开挡路的格、向下挖、搭桥、垫柱,改动不持久(每步前提只读原始地图,状态只有位置)。图外是墙。代价是整数毫刻,目标是最短时间。完整定义见 [RULES.md](RULES.md)。
The body occupies two cells; it stands when both are free and it rests on a solid cell, or floats in still water, or hangs on a climbable cell. Moves: 4-way walk, 4-way diagonal without corner cutting, step up one, walk off an edge and fall (at most 3 cells onto a solid, any depth into water), ladders, 6-way swimming in water. **Track A** does not edit the world; **track E** adds digging out obstacles, digging down, bridging and pillaring, with edits that are not persistent (each step reads the original map only, the state is just the position). Outside the grid is a wall. Costs are integer millitick; the goal is the shortest time. The full definition is in [RULES.md](RULES.md).

地形类别(每格一个字节)/ terrain classes (one byte per cell): 空气 air、软 soft、石 stone、硬 hard、基岩 bedrock、静水 water、禁入 forbidden、可攀爬 climb、门 door、高障碍 tall;方块状态到类别由原版碰撞形状、硬度与语义算出,见 `blockmap.csv`。

## 题 / Problems

840 道(7 块 × 3 档 × 40)。一行一道题,坐标是局部坐标:
840 problems (7 regions × 3 buckets × 40). One problem per line, coordinates are local:

```
id,region,bucket,split,sx,sy,sz,goal,gx,gy,gz,radius
hills-short-001,hills,short,dev,361,130,414,at,350,128,414,
```

- **距离档 / bucket**:起终点的三维直线距离,短 ≤32、中 32–128、长 128–400 / 3D straight-line distance, short ≤32, medium 32–128, long 128–400。
- **目标 / goal**:走到某格(`at`)、走到某格附近 r 格内(`near`)、挖到某格(`dig`,只对封闭在实心里的一格,只有赛道 E 适用)/ walk to a cell, walk within r of a cell, dig a cell (a cell sealed in rock; track E only).
- **dev / held**:地块 1–6 的题按题号哈希五五开,一半调参用(`dev`),一半封存(`held`,只在定版前跑);`mixed` 全部是 `held` / regions 1–6 split 50/50 by id hash into tuning (`dev`) and held-out (`held`); `mixed` is all `held`.
- 题是用 Numen 的搜索按纯物理耗时挑出来的(只收在 Numen 的走法下有定论的题),所以"哪些题有趣"带着 Numen 的走法;答案则不是——GRAV3D 的答案由独立的参考求解器在 GRAV3D 规则下重新算出。/ The problems were selected with Numen's search under pure physical time (only those conclusive under Numen's moves were kept), so "which problems are interesting" carries Numen's moves; the answers do not — the GRAV3D answers are recomputed by an independent reference solver under the GRAV3D rules.

## 答案 / Reference answers

每道题在两个赛道上各一行:`optimal`(最优价,单位毫刻,与挖、放块数)、`unsolvable`(整个可达范围搜尽,没有目标;图是封闭的,所以这是证明)或 `n/a`(这一赛道不适用:起点在规则下站不住,或赛道 A 上的 `dig` 目标)。`optimal` 的每一行都有一条参考路径。
One row per problem and track: `optimal` (cost in millitick, plus digs and places), `unsolvable` (every reachable state was searched without meeting the goal; the grid is closed, so this is a proof) or `n/a` (not applicable on this track: the start cannot stand under the rules, or a `dig` goal on track A). Every `optimal` row has a reference path.

v3 的数 / counts in v3 (840 problems per track):

| 赛道 / track | optimal | unsolvable | n/a |
|---|---|---|---|
| A | 545 | 218 | 77 |
| E | 833 | 1 | 6 |

每块地的数在 `grav3d/manifest.json`。赛道 A 的 77 条 `n/a` 里 73 条是 `dig` 目标,另 4 条和赛道 E 的 6 条是起点的脚格是半高的实心方块(GRAV3D 按碰撞高度 ≥ 0.5 归实心,所以站不上那一格)。
Per-region counts are in `grav3d/manifest.json`. Of the 77 `n/a` on track A, 73 are `dig` goals; the other 4, and the 6 on track E, are starts whose feet cell is a half-height solid block (GRAV3D classes collision height ≥ 0.5 as solid, so that cell cannot be stood in).

答案由 `tools/solver/Solve.java`(权重 1 的 A*,一致估价,平铺数组)算出,再由独立写的 `tools/validate.py` 逐条验证:1 378 条 optimal 路径全部合法、代价与参考最优价一致;短档题另用零估价(Dijkstra)重算,320 条"题×赛道"结论完全相同。一致性小图见 `tests/conformance/`。
The answers were computed by `tools/solver/Solve.java` (weight-1 A*, consistent estimate, flat arrays) and checked path by path with the independently written `tools/validate.py`: all 1,378 optimal paths are legal and their cost equals the reference optimum; short-bucket problems were also recomputed with a zero estimate (Dijkstra), and all 320 problem×track verdicts are identical. Conformance maps are in `tests/conformance/`.

## Numen 层 / The Numen layer

`problems/<地>.jsonl` 一行一道题(世界坐标,Numen 的评测读它),带终点种类与几何标签:
`problems/<region>.jsonl` has one problem per line (world coordinates), with end class and geometric tags:

```json
{"id":"hills-medium-012","region":"hills","bucket":"medium","distance":93.4,
 "from":[x,y,z],"goal":{"type":"at|near|dig","to":[x,y,z],"radius":3},
 "endClass":"surface|cave|cavity|buried","split":"dev|held","tags":["water","rough","dig","underground"]}
```

- **终点种类 / endClass**:地表(含水面)、洞穴地面(连着大片空间)、封闭的地下空腔、封闭在实心里的一格 / surface (incl. water surface), cave floor (connected to a large open space), sealed cavity, a cell sealed in solid rock.
- **标签 / tags**:只看地形与题:起终点之间的直线上有水或岩浆(`water`)、直线不平稳(`rough`)、终点被封死要挖才进得去(`dig`)、终点在地下(`underground`)。/ geometric only: fluid on the straight line, a rough line, a sealed end that must be dug into, an underground end.
- **规格 / spec**:Numen 的搜索有两种规格,`A` 不挖不垫,`B` 出厂规格(可挖可垫);同一道题两种都跑,需要编辑才做得成的题只给 `B` 跑。/ Numen's search has two specs, `A` no digging or placing, `B` the factory spec (may dig and place); every problem runs under both, except goals that need editing, which run under `B` only. (这与 GRAV3D 的赛道 A、E 是两回事 / not the same as GRAV3D tracks A and E.)
- **`answers.jsonl`**:一行一条"题 × 规格":`{"id":..,"spec":"A|B","status":"optimal|unsolvable","cost":..,"dug":..,"placed":..,"expanded":..,"startEstimate":..}`,是权重 1 的 A* 在整块区域上、Numen 的走法下按**纯物理耗时**(刻;放、挖、起跳、涉水、挨着伤身格走的罚分全为 0,挖掘遮挡的偏好也为 0)算出的价钱(先 2 000 000 个节点,撞上限的再 8 000 000 个),`dug`、`placed` 是那条路线挖、放了几块;`unsolvable` 是区域内证明的无解(连通块没碰到区域边)。它是"Numen 物理模型 `numen-physical-1` 的参考值",**不是真最优**(Numen 的状态抽象有混叠,见其 ADR 0036),真最优请看 GRAV3D 层。`answers-manifest.json` 记着口径、算出它们的 Numen 提交与两档节点上限。评测的次优比是路线的物理刻数除以它,所以调罚分、权重都不必重算数据集;没有它评测照跑,只是报表里没有次优比。/ one line per problem × spec: the optimal cost from weight-1 A* over the whole region under Numen's moves and cost model (first 2,000,000 nodes, those that hit the cap again with 8,000,000); `unsolvable` is a no-route proven inside the region (the connected component did not touch the region edge). The price is **pure physical time** in ticks (penalties for placing, digging, jumping, wading and walking beside harmful blocks are all 0, and so is the sight-blocker preference of dig goals); `dug` and `placed` count the edits of that route. These are "reference values of the Numen physical model `numen-physical-1`", **not a true optimum** (Numen's state abstraction aliases states, see its ADR 0036); for the true optimum use the GRAV3D layer. `answers-manifest.json` has the model, the Numen commit and the two node caps. The benchmark's suboptimality is the route's physical ticks divided by this price, so tuning penalties or weights never requires recomputing the dataset.
- **只收有定论的题 / only conclusive problems**:候选题在每个适用规格下答案都是最优价或区域内证明的无解才收;路伸出区域的(区域外没加载,没有定论)、两档上限都算不动的、只有上界的、平凡的都拒掉,继续抽候选直到每块地每档凑满 40 道。v3 抽了 1 160 个候选,拒掉 320 个(平凡 21、路伸出区域 239、两档都算不动 3、只有上界 57);1 551 条答案里最优 1 371、无解 180。出题在 20 核、90 GB 的机器上用了约 6.2 小时。每块每档的数在 `manifest.json`。/ a candidate is kept only when its answer under every applicable spec is an optimal price or a no-route proven inside the region; routes leaving the region, those no node cap solves, those with only an upper bound, and trivial ones are rejected, and candidates are drawn until each region and bucket has 40. v3 drew 1,160 candidates and rejected 320 (trivial 21, beyond the region 239, too hard 3, upper bound only 57); of 1,551 answers 1,371 are optimal and 180 unsolvable. Generation took about 6.2 hours on a 20-core, 90 GB machine. Per-region and bucket counts are in `manifest.json`.

出题与求解器的细节、假设(身体、垫路料、加载的区块、许可)见 [GENERATION.md](GENERATION.md) 与 Numen 仓库的 `docs/adr/pathing/0031-planning-benchmark.md`。
Generation details and the assumptions (body, materials, loaded chunks, permissions) are in [GENERATION.md](GENERATION.md) and Numen's `docs/adr/pathing/0031-planning-benchmark.md`.

## 怎么用 / Usage

提交自己的求解结果 / checking your own planner:

```
# 提交文件:每行一个 JSON,{"id":..,"track":"A|E","path":[[x,y,z],...]} 或 {"id":..,"track":..,"status":"unsolvable"}
python3 tools/validate.py --map neutral/hills --scenarios scenarios/hills.csv \
        --answers grav3d/answers/hills.csv --paths my-hills.jsonl --out verdicts.csv
```

每题的结论是 `valid`(附代价与最优价之比)、`invalid-<i>`(第 i 步非法,附原因)、`unsolvable-ok` 等,见 [FORMAT.md](FORMAT.md)。重新求解、跑一致性测试 / re-solve and run the conformance tests:

```
javac -d out tools/solver/Solve.java
java -cp out Solve --classes neutral/classes.json --costs grav3d/costs.json --map neutral/hills \
     --scenarios scenarios/hills.csv --tracks A,E --answers a.csv --paths p.jsonl --threads 8
python3 tests/conformance/run.py
```

求解器每个线程每个赛道占约 0.8 GB(两个与格子同大的整数数组);全部 1 680 个"题×赛道"在 20 核上约 3.7 分钟。
The solver uses about 0.8 GB per thread and track (two int arrays the size of the grid); all 1,680 problem×track jobs take about 3.7 minutes on 20 cores.

Numen 仓库里的 Numen 层评测(读 `problems/`、`terrain/`、`answers.jsonl`,Gradle 按版本与 sha256 下载)/ Numen's own evaluation (reads `problems/`, `terrain/` and `answers.jsonl`; downloaded by version and sha256 from Gradle):

```
./gradlew :numen:pathing:pathingBench                              # 下载数据集,跑 dev 题 / download the dataset, run dev problems
./gradlew :numen:pathing:pathingBench -PpathingDataset=<本地目录>   # 用本地的数据集目录 / use a local dataset directory
./gradlew :numen:pathing:pathingExport -PpathingDataset=<目录> -PpathingExportOut=<目录>   # 重新导出中立地形 / re-export the neutral terrain
```
